# Engineering Decisions

Decisions made for the platform architecture, reputation policy, and when the specification or paper leaves details open (REQ-001).
Format: decision id, task / scope, binding decision, and rationale.

| ID | Task / Scope | Decision | Reason |
|---|---|---|---|
| DEC-001 | Scoring / Social (Likes) | Likes on original posts that are ultimately assessed as `fake` by an admin are penalized with a `MISINFO_LIKE` (-1) reputation event. Liking an already-fake post immediately creates an eligible `MISINFO_LIKE` event. Unliking retracts the like (`deleted_at` set) and voids any unfinalized eligible event (`void_reason = 'interaction_retracted'`). | Enforces social accountability for amplifying falsehoods while providing a clean retraction path before wave finalization. |
| DEC-002 | Scoring Engine (Equations 1 & 2) | Publisher reputation independence: a user's reputation depends exclusively on their own eligible actions and fixed sensitivity $\sigma_i$, never weighted by the publisher's reputation $Q$ or tier. | Faithful to the paper's mathematical formulation: $R_i(w) = n_i^+(w) - n_i^-(w)$ and $Q_i(w+1) = Q_i(w) + \sigma_i \cdot R_i(w)$. |
| DEC-003 | Scoring / Social (Reshares) | Verified-true reshares are rewarded: users who reshare an original post verified as `real` by an admin (`source = 'admin', verdict = 'real'`) receive `RESPONSIBLE_RESHARE` (+1), subject to `MAX_RESPONSIBLE_RESHARE_EVENTS_PER_WAVE = 5`. `auto_real` posts do not reward reshares. | Rewards responsible diffusion of human-verified factual content while bounding Sybil/collusion amplification via per-wave caps. |
| DEC-004 | Scoring / Governance (Viral posts) | Publishers of admin-assessed `fake` posts receive a flat -1 (`MISINFO_POST`) per false post. Penalty never scales with likes, reshares, reach, or engagement volume. | Avoids runaway unbounded penalties and maintains deterministic unit event values per Equation 1. |
| DEC-005 | Scoring / Social (Retraction) | Deleting a reshare before wave finalization voids any `eligible` or `held` event (`void_reason = 'interaction_retracted'`) and auto-closes open appeals. Counted events in finalized waves remain strictly immutable. | Balances user redemption before wave closure with ledger immutability and reproducibility. |
| DEC-006 | Scoring / Social (Comments) | Comments, follows, messages, and blocks never generate reputation events. Comments are excluded from scoring. | Stance and sentiment analysis of unstructured comments would require NLP outside deterministic paper scope. |
| DEC-007 | Phase 4 / TASK-028–036 | Superseded. The detector uses `hamzab/roberta-fake-news-classification` at pinned revision `648014ea36ff8aff85b6a6ee25e77579c27bcf19`, loaded locally from SafeTensors. | The project owner selected a pretrained model. Training from scratch is removed from the runtime path. |
| DEC-008 | Auth / Sessions (TASK-039) | `GET /auth/sessions` returns a top-level JSON array `SessionItem[]` (conforming to '200 list' in plan Section 1.7), sorted newest first. `DELETE /auth/sessions/:id` revokes the specified session if owned by the caller; if revoking the current session, it also clears the session cookie. | Consistent with plan Section 1.7 endpoint table and strict session isolation. |
| DEC-009 | Media / Storage (TASK-041) | Media S3 object key is set to the media item UUID (`media.id`), with `Content-Type: image/webp`. The public URL is `${config.S3_PUBLIC_BASE_URL}/${media.id}`, allowing direct retrieval from SeaweedFS / MinIO / S3 without redirects. | Unifies media identification and retrieval, eliminates URL rewriting overhead, and ensures clean cleanup. |
| DEC-010 | Detection integration / TASK-049–050 | The API owns the queue, retry state, and detection bands. The detector returns only `p_fake`; a likely-fake result may notify the author, but never creates an assessment or reputation event. | Keeps prediction and governance separate under RUL-001, RUL-002, REQ-008, and REQ-009. |
| DEC-011 | Scoring / Corrections (RUL-015 step 2) | When an assessment is superseded, counted `REVERSAL` events of the old assessment are **not** reversed again; only counted non-reversal events receive a `REVERSAL`. Eligible or held reversals are still voided with `assessment_superseded`. | The plan's literal "every event of A_old" made a three-deep chain (fake → real → fake) net −2 for one false post, contradicting DEC-004's flat −1. Skipping reversal-of-reversal keeps every chain at the net value of the current verdict. |
| DEC-012 | Detection client (`detection/client.ts`) | Non-401, non-422 client-side HTTP errors from the detector (other 4xx) are recorded with `error_code = 'HTTP_5XX'`, the plan's catch-all for unexpected upstream responses. | Section 1.6 enumerates only `TIMEOUT`, `NETWORK`, `HTTP_401`, `HTTP_422`, `HTTP_5XX`, `MALFORMED_RESPONSE`, `REQUEST_ID_MISMATCH`; adding codes would change the contract, so the catch-all is reused and the status is kept in `error_detail`. |
| DEC-013 | Abuse defence (`middleware/rateLimit.ts`, `config.ts`) | The global per-IP ceiling (Section 1.7: 300 requests per minute) is read from `GLOBAL_RATE_LIMIT_PER_MINUTE` with the plan's default; per-route limits stay hard-coded. | The integration suite issues thousands of requests from one IP; a configuration value lets tests raise the ceiling without an `if (NODE_ENV)` branch (GUD-008). |
| DEC-014 | Metrics (`metrics.ts`) | `GET /metrics` accepts only `Authorization: Bearer <METRICS_TOKEN>`; a `?token=` query parameter is rejected. `METRICS_TOKEN` is mandatory in production (startup fails without it). | Section 1.7 lists Bearer only; query-string secrets leak into access logs and proxies. |
| DEC-015 | Score read endpoints (`modules/score`, `modules/users`) | `GET /me/score` returns an extra `pending.projectedQ` (the current Q plus the projected delta) computed server-side with `decimal.js` through `applyUpdate`. | Lets the client draw the projected point of the wave ledger without any client-side arithmetic (Section 1.1, REQ-003, REQ-004). |
| DEC-016 | Admin endpoints (`modules/admin/routes.ts`) | `POST /admin/users/:id/suspend`, `/unsuspend` and `DELETE /admin/posts/:id` require a `{reason}` body (5–1000 chars) recorded in the audit row; admins cannot be suspended; `GET /admin/posts/:id` adds `interactors` counts and a `conflictOfInterest` flag; admin list endpoints return camelCase objects. | Implements the bodies and rules Section 1.7 names, and gives the review workspace the numbers for its consequence summary (Section 1.8) without a second round trip. |
| DEC-017 | Email verification (`modules/auth`, `middleware/auth.ts`, migration 0006) | Removed. Registration creates an active session and no verification token or mail; `Act` access means signed in with status `active`; `POST /auth/verify-email`, `POST /auth/resend-verification`, `REQUIRE_EMAIL_VERIFICATION`, the `EMAIL_NOT_VERIFIED` error and `users.email_verified_at` are gone. Password reset mail is unchanged. | Product decision on 2026-11-05: the verification step was overhead for a research platform and added nothing the rate limits and admin suspension do not already provide (RISK-004 updated). |
